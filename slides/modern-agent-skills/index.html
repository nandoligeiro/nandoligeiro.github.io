Skill pattern
Progressive disclosure

O agente não precisa carregar tudo de uma vez.

1. Frontmatter

Metadados pequenos para descoberta e ativação.

namedescription

2. SKILL.md

Instruções carregadas quando a skill é relevante.

workflowrulescriteria

3. Attachments

Scripts, templates e referências consultados sob demanda.

scripts/references/

Adaptação para Devin Local: o agente carrega o mínimo para decidir, depois usa repo, terminal e arquivos locais conforme o fluxo exige.

Menos contexto inútil. Mais execução precisa.04
Nota: carregar só o que ajuda o próximo passo.
Focused skills
Composição

Skill boa é pequena o suficiente para ser testada.

❌ Mega skill

“Arquitetura completa”

Vira manual infinito, ativa mal, mistura domínios e fica difícil de depurar.

✅ Skill focada

“PR Review Java/Kotlin Cartões”

Tem entrada clara, workflow claro, checks claros e saída esperada.

A regra é simples: se não dá para testar, ainda está grande demais.
Composição > monólito de prompt05
Nota: começar com fluxos repetíveis: PR, API, RCA, Kafka/MQ e observabilidade.

Package
Skill package

Estrutura mínima de uma Skill

Um exemplo prático de como organizar instruções, scripts, referências e templates para execução no Devin Local.

credit-card-pr-review/ ├── SKILL.md ├── scripts/ │ ├── run_tests.sh │ ├── validate_openapi.sh │ ├── check_architecture.py │ └── collect_evidence.sh ├── references/ │ ├── api-guidelines.md │ ├── clean-architecture.md │ ├── observability.md │ └── security.md └── assets/ └── pr-review-output.md
SKILL.md: coordena o fluxo.
scripts/: valida o que não pode ficar subjetivo.
references/: guarda padrões e contexto.
assets/: formata a saída para devs e PRs.
Skill como código: versionada, revisada e testável10
Nota: a skill muda comportamento do agente, então deve passar por review.
Creation flow
Criação de skill

Quando já sabemos o processo, escrevemos a skill de frente para trás.

1

Escolher uma tarefa repetível: PR review, nova API, RCA, integração Kafka/MQ.

2

Descrever o resultado esperado: parecer, patch, relatório, checklist ou evidência.

3

Mapear workflow: passos principais, branches e condições de parada.

4

Separar validações: o que vira script, teste, schema ou checklist.

5

Rodar em caso real: medir se a skill ajudou sem precisar de muita intervenção.

Creation: do procedimento conhecido para o package11
Nota: melhor rota quando o time já tem um padrão claro, mesmo que informal.
Reconstruction flow
Reconstrução de skill

Quando o processo está espalhado, começamos pelos traces.

1

Coletar execuções: conversas, commits, PRs, comandos, logs, tool calls e anotações.

2

Identificar padrões: passos recorrentes, decisões, falhas e verificações.

3

Decompor em R/W/S/A: gatilho, fluxo, regra e anexos.

4

Gerar draft: SKILL.md + scripts + referências mínimas.

5

Replay: testar contra tarefas conhecidas e ajustar o componente que falhou.

Reconstruction: da execução observada para o procedimento explícito12
Nota: conecta ao paper W2S: preservar comportamento útil de uma execução real.

Governança
Segurança e operação

Adaptar para Devin Local também significa impor limites claros.

O que a skill nunca deve carregar

Tokens, senhas, certificados ou segredos.
Dados sensíveis de cliente.
Endpoints internos críticos sem necessidade.

O que a skill deve deixar explícito

Permissões de leitura, escrita e execução.
Quando pedir aprovação.
Como registrar evidências.
Produtividade sem governança vira débito técnico com capa de inovação.
Em banco, previsibilidade é feature14
Nota: governança é trilho para o agente trabalhar com segurança.
